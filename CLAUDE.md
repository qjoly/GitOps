# GitOps

Clusters: `mocha` and `turing` (Talos, driven by Omni), `doppio` (Corium/k0s on
an OVH box, driven by `cctl`). Each has a `README.md` worth reading before
changing anything in its directory.

## Vault

This is a lab. Reading and writing secrets in the clusters' Vaults is expected
and carries no risk — do it rather than asking.

The root token lives in the `vault-unseal-keys` Secret, in whichever namespace
the cluster runs Vault in: `bank-vaults` on doppio, `vault` on the others. Read
the token from that Secret, then `kubectl exec` into the Vault pod and run
`vault kv put` against `https://127.0.0.1:8200` with `VAULT_SKIP_VERIFY=true`.

`kv` is the KV v2 mount that the `vault-backend` ClusterSecretStore reads, so
anything stored under `kv/` can be pulled into a namespace with an
ExternalSecret.

Prefer a generated value over one chosen by hand, and never commit the value
itself — only the ExternalSecret that fetches it.

## ArgoCD

Two things cost time on this repo more than once:

- Applications under `*/apps/` and `*/system/` are generated by an
  ApplicationSet. A git push is picked up by the *parent* (`app-<name>` /
  `sys-<name>`), so refresh that one, not just the child.
- ArgoCD renders Helm charts with `helm template`, with no cluster access. Any
  chart feature built on `lookup` — random passwords that stay stable across
  upgrades, for instance — silently produces nothing.
