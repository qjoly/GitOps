Definitive URL for a Mac port on NetBird: mac-relay

Started: 2026-11-20 Scope: new app mocha/apps/mac-relay, plus the mise run nb:mac task on macOS.

What was done

https://mac.nb.mocha.thoughtless.eu/ now reaches a local port of the Mac from every NetBird peer, without installing the NetBird client on the Mac and without depending on its NetBird IP:

  • mocha/apps/mac-relay (auto-discovered by the mocha-apps ApplicationSet): a chisel server (--reverse) whose control port 2333 is reachable only via kubectl port-forward, and whose reverse listener :8080 is published by a traefik-internal Ingress on mac.nb.mocha.thoughtless.eu. The *.nb wildcard already resolves to traefik-internal everywhere (NetBird zone CNAME, CoreDNS sidecar of netbird-jump, /etc/resolver + pf on the Mac) and traefik-internal already serves the *.nb wildcard cert — so the URL is definitive with no DNS record to maintain. Auth via the mac_relay_auth property of kv/netbird (ExternalSecret mac-relay). NetworkPolicy: only traefik-internal may reach the pod, and only on 8080.
  • mise run nb:mac (macOS): keeps a kubectl -n mac-relay port-forward deploy/mac-relay 2333:2333 open and runs chisel client … R:8080:127.0.0.1:$NB_MAC_PORT in a reconnect loop. chisel is installed by mise install.

Usage

# once, in Vault
mise run vault:kv patch kv/netbird mac_relay_auth="mac:$(openssl rand -hex 24)"
# on the Mac
export NB_MAC_RELAY_AUTH='mac:…'
NB_MAC_PORT=3000 mise run nb:mac
# from any NetBird peer
curl https://mac.nb.mocha.thoughtless.eu/

While no Mac is connected, traefik answers 502 on the URL (nothing listens on :8080 in the pod). One Mac at a time — the relay is a single replica.
